# 技能列表只为实际返回的条目读取正文

Status: implemented

## Problem

项目查询返回继承进来的全局技能。此前先做本地定位、逐条读调用权限，然后才删除继承行；同一根下的扁平文件还分别反查目录。结果行数相同，磁盘工作量却随项目数放大。

## Decision

[技能目录](../../../lib/skills-registry.js) 继续以宿主裁决的 `source` 判归属，但先过滤掉这些全局摘要，再做定位和读取。扁平技能的物理路径索引由一次目录调用拥有，每个展示根最多扫一次；写操作仍重新校验落点，不使用这个索引作为权限依据。

## Alternatives considered

- 给技能行加跨请求 TTL 缓存，能进一步减少重复请求读盘；但文件刚改完时会回报过期的启停状态，且没有可靠的客户端失效事件。
- 用宿主报告的 `path` 尾段直接定位，能完全避免扫描；但符号链接的展示名可以不同，不能用目标文件名代替实际条目名。

## Consequences

- 项目数不再放大全局正文读取，同一请求共享根扫描；仍保留宿主遮蔽规则和即时文件状态。
- 每个需要反查的根会建立短生命周期的完整索引；单条技能在很大的根里可能比第一次命中即停止多扫描一些条目。
