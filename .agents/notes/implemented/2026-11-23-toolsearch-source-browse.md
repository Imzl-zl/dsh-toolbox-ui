# 来源公平提示与按需浏览补足陌生能力入口

Status: implemented

## Problem

工具名索引即使排序正确，模型也可能不知道需要搜什么。此前 800 字符提示先取全部宿主项，MCP 还受三例上限和非空 instructions 去重约束；陌生服务可能只剩名字。无限增加常驻说明又会扩张所有用户的上下文。

## Decision

保留[通用原文规则](2026-11-22-toolsearch-generic-purpose-hints.md)，但来源预算每轮先各有一次实际装入机会，再取宿主的下一项。MCP 单来源最多一项，同源首个长例放不下可试后续完整例子；展示始终按真实来源分组。

[只读浏览](../../../lib/tool-search-browse.js) 用同一 agent/step 的实际 catalog，显式 mode=browse，仅分页给源码用途和声明参数名；不注册、不执行、不写发现或恢复种子。cursor 绑定会话实例、内容版本和过滤；本地引用/组合分支只用于元数据，不重建 calling schema。空或不可引用用途仍能按完整名字加载。默认 query/select 的完整加载承诺不改。

## Alternatives considered

- 给全部工具常驻完整描述最容易让模型认识能力，但每用户规模和说明长度不可控；用有限地图加可按需扩展的入口。
- 只优化排名开销小，却不能解决模型根本不发起查询的缺口；显式浏览提供不必先猜关键词的路。
- 预置 MCP 用途表或 embedding 能做跨语言关联，但不满足任意库存和零部署约束；不引入模型、端点或人工同义词表。
- 把 browse 当每题第一步能减少漏看，却会让纯计算、计划和已有充分信息的任务过度调用；引导只针对欠缺的外部事实、验证或动作，并允许正确终止。

## Consequences

- 同源预算和元数据入口有真实宿主、分页/作用域、恢复、原文与空长说明回归，默认加载/权限语义不变。
- 800 字符仍不可能覆盖所有用途，第一句不保证完整语义；browse 可能多占一轮，仅给声明字段也不替代完整验证。主模型仍负责判断需要和选择。
- 单模型八对中必要调用两臂均5/5、控制案零调用；新版实际browse两次，但严格完成数变化是JSON fence，不作为主动性提高证据。没有承诺所有用户模型效果或通用成本降低。
