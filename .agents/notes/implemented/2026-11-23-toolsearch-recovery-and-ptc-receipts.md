# ToolSearch 区分持久恢复种子与模型可见回执

Status: implemented

## Problem

v2 把累计快照放进宿主 meta 后，native 的派生消息备用路径仍要求同一份快照，结果连当前回执可证明的新增也丢了。新版宿主返回可调用 thenable，单凭返回值是函数判旧版会误报就绪；即使识别了异步句柄，首次在注册未完成时播种也会把临时空状态固定到 agent。PTC 回执另有一处类似的边界错误：把程序内的绑定当成可直接调用的工具名，且压缩了类型字面量中的空白。

## Decision

[恢复读侧](../../../lib/tool-search-state.js)只从 v2 正文接收该回执成功匹配的新增名单，作有界降级恢复；完整替换仍依赖持久投影。[投影端口](../../../lib/tool-search-projections.js)先识别可等待的注册，只有有效句柄才可读；同步守卫等待期间不播种。[回执](../../../lib/tool-search-runtime.js)用宿主的类型文本，唯一允许压缩的是布局换行；PTC 使用带引号的下标表示 SDK 绑定，不宣称原生直调。

## Alternatives considered

- 把累计快照放回模型正文可使派生消息精确恢复，且不用等待投影；但会让长会话反复接收状态副本。保留 meta 作为完整真源，只复用正文已经暴露的增量。
- 力保每个入口同步可避免注册等待影响第一步；但同步取得的空状态无法区别“历史为空”与“句柄尚未就绪”。异步入口只在注册 pending 时等待，守卫保持同步。
- 按名字语法选择点号或下标会让常见绑定短几个字符；但需复制两种语言的标识符规则。宿主两种 SDK 已支持下标，统一用它保留确切名称。

## Consequences

投影未就绪不污染现场状态，现代注册/释放失败有明确诊断，且不增加模型可见的发现快照。没有投影的 native 只能还原最近新增，无法还原真实淘汰顺序；没有投影的 PTC 仍无法恢复嵌套派发。初始化可能在首步等待一次宿主注册，普通步骤无此等待。签名继续是一行，但是不为了进一步省字符修改类型字面量。
