# 项目连接只投射本连接的工具定义

Status: implemented

## Problem

宿主的 scoped 工具视图包含继承的全局定义。原先只有服务器完全同名时才过滤继承项；合法的 `docs` 和 `docs__shared` 在 wire 前缀上也会重叠。把继承项重新注册到会话自身层，会让它脱离只约束继承项的项目 `exclude`，详情还会把它算成项目工具。

## Decision

[连接读取](../../../lib/workspace-runtime.js)用名称前缀选候选，再与全局工具的定义身份比较。全局同一对象永远不算连接自有定义，前缀重叠和完全同名遵守同一规则。面板和会话投射使用同一个结果。作用域诊断也不把可能属于其他已知连接的全局工具断言为本连接泄漏。

## Alternatives considered

- 只在发现有重叠的配置时比较定义：可以省一次全局读取，但无法覆盖晚到的定义或不在配置目录的注册来源，名字仍会被误当成归属。
- 在 RPC 返回或 `exclude` 处再过滤：只改一处看起来简单，但会话和面板仍从不同来源判断归属，而且不能可靠修正已投射到自身层的工具。
- 为 Cordis 4.2 覆写符号根来保留老的判重兜底：能改变 MCP 判重键，但同一根也是宿主服务隔离映射的入口，不应为一个用例改变它。现有支持范围未扩大；重复 `dsh-scope` 的 4.2 预发行组合仍需验证实际依赖身份后再支持。

## Consequences

- [真宿主回归](../../../test/real-host-integration.test.mjs)覆盖合法前缀重叠，使排除设置、会话声明和项目详情一致；正当的同名项目定义仍保留。
- 缓存失效后需要比较全局与项目定义。新宿主用公开 `definitions` 两次读取，避免逐条深拷贝和反复重建视图；旧宿主使用 `schemas` 与 `get`，多付候选项的全局查询。稳态仍按连接代次哨兵短路。
- 诊断在名称归属仍有歧义时不作泄漏结论；这是诊断的限制，不是允许把继承定义投射回项目的例外。
