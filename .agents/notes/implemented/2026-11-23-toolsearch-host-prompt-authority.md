# ToolSearch 服从宿主最终系统提示

Status: implemented

## Problem

现代宿主在 waterfall 结束后才决定最终系统段和模型工具声明。插件为裁工具在 `assemble` 外层接入时，也可能把目录和第三方描述追加到宿主已经裁定的独占提示中。最终段不保留 `complete` 标志，名字和正文还可以被作用域覆盖；这两者都不能单独证明引导来自插件。

## Decision

[装配适配器](../../../lib/tool-search-adapter.js)在每次调用内记录本插件实际注册的引导 provider 是否参与，再核对其段是否在宿主最终结果保留。没有证据便保留宿主提示、跳过目录投影。运行时只对同一准入步骤中已完整声明且仍匹配的定义免除本插件自己的发现检查；不把宿主标记延迟的定义算作完整声明。PTC 仍允许显式搜索，不补写宿主未提供的手册，也不根据自定义文案猜测权限。

## Alternatives considered

- 靠结果段数量、名称或字面内容推断独占：实现简单，不用跟随服务重绑；合法配置可以只有一个普通段，也可以用同名同文的 scope 覆盖，因此不能证明来源。
- 只保留宿主正文、继续隐藏所有延迟工具：守卫更简单，但完整系统提示可能没有发现指引；对已经完整声明的工具也会形成错误拒绝。
- 按 agent 缓存最后一次透传：查询更方便，但同一 agent 的两个准入步骤可以同时存在，不能用其中一步推断另一步的声明或许可。

## Consequences

- 不覆盖独占系统提示；native 保留实际声明，PTC 保留调用路径，且不会因为一次透传使其他步骤发现或获准执行工具。
- 现代接入口需要在服务重绑时管理引导注册，并付一次装配来源跟踪；旧宿主由自身恢复独占段，不使用现代的逐步守卫例外。
- [真实宿主回归](../../../test/tool-search-rc22-host.test.mjs)验证有效提示、声明与守卫；未验证任意第三方描述对模型推理的影响。
