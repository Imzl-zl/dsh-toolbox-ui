# 延时刷新与详情结果都由发起时的视图拥有

Status: implemented

## Problem

列表序号只能区分已发出的请求；提交操作以后尚未执行的定时回调可以在切到另一作用域后拿到更新的序号。技能详情把正文当作独立的可变值，旧行的响应也能写进新行。

## Decision

[MCP 列表](../../../lib/client/70-shell.js) 在发请求和收结果时核对当前视图身份，切换事件同步撤销旧身份；卸载由布局 effect 收回。技能详情对每次请求使用独立身份，只把和当前行键、调用源都一致的正文交给视图；调用源更换时重读当前行。相同的工作区路径集合保留引用，连接状态只由 MCP 面轮询，共享横幅的手动重试不受此限制。

## Alternatives considered

- 只给请求增序号，开销很小，也能挡住乱序响应；但接不到真实发起请求前已经过期的闭包。
- 只取消定时器和传输，能减少无用工作；但不能回滚已经完成的回调，而且宿主 RPC 不提供此处所需的通用取消契约。结果归属仍须独立核对。
- 把每个视图状态交给一套统一查询库，便于统一缓存和错误口径；但当前对外契约不提供请求取消，两个修复的身份范围也不同，引入依赖并不能替代归属验证。

## Consequences

- 切换作用域或选中项不再被旧数据覆盖；离开 MCP 面不再持续读取它的状态，工作区路径不变不会间接触发技能重读。
- 客户端要区分「所属视图」「请求顺序」「手动刷新」；旧 RPC 已发出时仍可能完成，只是不会写进当前视图。
