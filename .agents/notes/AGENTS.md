# 决策笔记目录规则

本目录只保存代码之外的取舍原因，现状/使用契约仍在项目 docs，测试和代码仍是行为证据。

- 状态由 proposed/、implemented/、rejected/、archived/ 的目录位置决定；Status 字段必须一致。
- 每篇使用 Problem / Decision / Alternatives considered / Consequences 四格。
- 替代方案先写最强理由再写否决原因；后果同时列收益与代价。
- implemented 只写已发生的决定，不写 Proposal / 计划 / TODO 标题；随受约束代码更新。
- archived 结论冻结；被取代时新建相邻版本笔记，旧篇仅标注取代关系。
- 不创建 INDEX、notes/README 或逐篇更新的总索引；不用标题前缀重复表达状态。
- 受约束入口用一行注释回指笔记；不得把笔记作为未经验证行为的依据。
