## 红线：通用性（最高优先级，先于任何方案）

本插件**同时给作者本人和陌生用户用**。作者机器上的服务器、语言、命名风格都是**样本**，不是需求。
任何方案必须先过这五条，过不了就不进实现：

| # | 判据 | 反例（已否决） |
|---|---|---|
| R1 | **不得枚举**：代码里不许写死任何具体工具名、服务器名、领域词、语言词表、停用词 | 停用词表 `mcp/tool/get/list`；中英同义词表；"serena=代码检索"这类策展词典；按已知 MCP 服务器名写分支 |
| R2 | **不得猜**：不许用启发式判断"这段文字有没有意义"（跳过某类段落、按标题/大写/长度猜重要性） | "跳过 `#` 开头或全大写段落、最多试 3 段" |
| R3 | **不得按作者机器取样设计**：验收必须包含与当前环境完全不同的配置 | 只按 serena / chrome-devtools / jshook 三台设计 |
| R4 | 每条方案必须能回答："**用户装的是我完全没想到的服务器，这条还成立吗？**" | 答不上来的不进方案 |
| R5 | **数据来源只认三种**：① 运行时注册表（工具名/描述/参数）② MCP 协议字段（`instructions` / `serverInfo`）③ 用户自己填的配置。除此之外一律按枚举论处 | 内置行业分类、预置服务器目录 |

**允许的唯一截断语义 = 资源预算**（固定字符数 / 行数上限），必须与内容语义无关。
"截到 80 字符"合规；"取第一段/取最有用的一句"不合规。

### R6 失败分级（用户 2026-10-26 明确要求）

任何改动前先回答：**它坏了会怎样？** 只有三档，不许含糊：

| 档 | 含义 | 处理原则 |
|---|---|---|
| **A 必须稳**（错 = 出真问题） | 归属、切分、遮罩、发现集、结果名 | 必须“验证后操作”，配可测不变量；宁可不错，不可猜 |
| **B 可以缺**（缺 = 少点意思） | 摘要文字、排序质量、跨语言召回、个性化加分 | 允许截断/缺失/退化，**不得为了它牺牲 A 的稳定性** |
| **C 缺了必须说**（沉默 = 骗） | 目录截断数量、搜索无命中、归属歧义、降级原因 | 必须显式提示 + 记账，**不许静默** |

**C 是最容易被混进 B 的一档**：目录被截断却不写“还有 N 个”，模型会以为没有那批能力——
这不是“少点意思”，是**给出错误结论**。

**A 档的可测不变量（写码时必须逐条有用例）**

| # | 不变量 |
|---|---|
| I1 | 分组结果只能是「正确的 owner」或 `null`，**不得是别的服务器** |
| I2 | **可逆性**：`'mcp__' + owner + '__' + bare === 原始工具名`（恒等，切歪必红） |
| I3 | 剥完 `bare` 非空（原始名为空的工具不剥） |
| I4 | 服务器列表不变时，同一工具名的分组/裸名结果恒定（跨会话、跨 revision） |
| I5 | 遮罩集合恒等于 `managed − discovered`，不存在第三态 |

**R3 的极端验收输入**（缺一不可）：

- 0 台延迟服务器（功能应完全不介入）
- 1 台服务器 / 1 个工具

- 全部服务器 `instructions` 为空
- 工具描述是中文 / 日文 / 阿拉伯文
- 工具名被 64 字符截断并带哈希后缀
- 两台服务器名前缀互相包含（`a` 与 `a__b`，触发 `uniqueOwner` 歧义）

### Q1 细分

- 项目族：`register(def, { when: ({agent}) => discovered(agent).has(name) })`。
- 全局族：`agent.ctx.tools.restrict({ deny })`，发现集变化时 dispose + 重挂。
- **代价（唯一真取舍）**：`when`/`restrict` 都让工具在 `executable()` 里就不存在 → guard 跑不到 → 失去"请先 `tool_search('X')`"的指引，退化成 `UNKNOWN_TOOL`。
- 若坚持保留指引，就必须继续做装配期遮罩，即跟着宿主新结构改实现。

### Q2 细分

根因：`catalogSectionLines()` 按**完整工具名**（`mcp__<server>__<tool>`）排序后全局切 300 行
（`lib/tool-search-runtime.js:347`）。同一服务器名字连续 ⇒ 排序靠后的服务器**整台消失**。

三个子问题（可分别拍）：

1. **摘要行放什么**：`instructions` 首段（截断 ~120 字符） / 服务器名 + 工具数 / 两者都要。
2. **截断策略**：维持全局 300 行 / 按服务器公平配额 / 摘要永不截断 + 名字按需付。
3. **被截断怎么告知** —— **已决：只报数，`server:` 枚举形态先不做**（2026-10-26 用户拍板）

   现状：组头同时给**总数**与**未列出数**（`### jshook · 360 tools · … · 156 not listed`，
   两者自洽：列出的行 + 156 = 360）。模型知道"还有多少"，但不知道那批**叫什么**——
   这正是 `server:<名>` 要解决的问题（返回该服务器全部名字、只名字、不受 `maxResults` 与预算限制）。

   **为什么先不做**：新字符预算下 456 个工具已经零截断，只有"用户调小预算"或"2000+ 工具的大
   部署"才会触发；为一个罕见路径加一套语法 + 解析 + 用例 + 文案不划算。

   **触发条件（重新拿出来谈的前提，别凭感觉）**：日志/面板里真的出现"因预算未列出 N 个名字"，
   或用户反馈"搜不到某台服务器上的工具"。

   **先做的便宜替代（比猜更值）**：把已经算出来的 `truncated` 变成**可观测**——`truncated > 0`
   时记一条 `warnOnce`（同一 revision 只记一次），面板可显示"当前目录因预算未列出 N 个"。
   成本≈0，好处是将来要不要做 `server:` 有数据依据，而不是靠"用户应该没那么多工具"。

| 中文查询 × 中文描述 | 二元分词已覆盖 | 可用 |

## 6. Q2 的验收标准（先定标准，再写码）

**格式（核心改动，先于截断策略）**：目录改为「服务器分组 + 裸名」。

**分组可靠性（源码级，两条保证）**

1. `publicToolName()` 是**唯一**命名路径：全仓非测试代码里它只在 `syncTools` 内部使用，
   项目族工具也是从共享 mcp-client 的注册结果投射，走同一套名字。没有第二条注册路径。
2. `serverName` 被 config schema 约束为 **`/^[A-Za-z0-9_-]{1,32}$/`**（`packages/mcp/mcp-client/src/index.ts:40`）。
   因此 DSH 前缀最长 = `mcp__`(5) + 32 + `__`(2) = **39 字符**，而截断保留区是
   `slice(0, 64-12-1) = 51` 字符 ⇒ **39 < 51，64 字符截断永远切不坏前缀**。
   （早前“serverName 超长会把前缀切坏”的担心不成立，作废。）

唯一残留歧义：`serverName` 允许含 `_`，所以同时配置 `a` 与 `a__b` 时，工具名 `mcp__a__b__x`
会双命中 → `uniqueOwner` 返回 `null` → 不分组、保留全名。**漏分，不错分**。

- 分组与剥离**不新增解析**：`owner = view.ownerOf.get(name)`；只有 `owner !== null` 才
  `name.slice('mcp__' + owner + '__'.length)`；`owner === null`（无 `mcp__` 前缀 / 两台服务器前缀
  互相包含而歧义）一律**保留全名**、归入未分组。禁止 `split('__')` 之类的字符串解析。
- 摘要行 = `- <owner> · <count> tools` +（`instructions` 非空时）` · ` + 压空白后**前 120 字符** +
  （`hidden > 0` 时）` · <hidden> names not listed (server:<owner>)`。
- `instructions` 为空 ⇒ **不写摘要**（只留 `- <owner> · <count> tools`），不发明描述。
- `interpolate: false` 保持（第三方文本，一个 `{{var}}` 会让组装抛错）。

**已排除的二次剥离（留档，防止后人再加）**

先纠正一条**曾经写错、已被实测推翻**的结论：早前这里写“真实数据上收益为 0”，那是只看了
chrome-devtools / jshook 两台就外推，**错了**。

实测取证（2026-10-26，从 `~/.dsh/sessions/**/session.v4.jsonl.zstd` 里读模型真正看到的
`request/header.tools[].name`；多帧 zstd 按帧魔数 `28 B5 2F FD` 切分逐帧解压后正则提取）：

| 服务器（配置名） | 观察到的原始工具名 | 是否重复服务器名 |
|---|---|---|
| `chrome-devtools` | `evaluate_script`、`list_pages`、`new_page` | ❌ 裸名 |
| `exa` | `web_fetch_exa` | ❌ 服务器名只作为**后缀**出现 |
| `jshook` | `console_inject_fetch_interceptor`… | ❌ 裸名 |
| **`firecrawl`** | **`firecrawl_scrape`** | ✅ **确实重复**（全族都是 `firecrawl_*`） |
| **`mcp-deepwiki`** | **`deepwiki_fetch`** | ⚠️ **变体重复**——前缀是 `deepwiki_`，配置名是 `mcp-deepwiki` |

**取证局限**（必须一起记）：session header 只记录**已声明**的工具，被延迟的工具不进 header，
所以样本量小（chrome-devtools 仅 3 个名字），**不能外推成“全部工具”**。要拿到完整花名册得靠
运行时 `ctx.tools.schemas()`，这里拿不到。

**结论：仍然不剥，但理由换成下面三条（旧理由作废）**

| # | 理由 |
|---|---|
| 1 | **精确匹配抓不住真实变体**：`mcp-deepwiki` 的工具前缀是 `deepwiki_`（去掉 `mcp-`）。要抓住它就得做「去 hyphen / 去前缀 / 归一化」的猜测，违反红线 R1 |
| 2 | **收益量级太小**：即便全部按精确匹配剥掉，`firecrawl_` 一族约省 240 字符，占目录总量（≈8.2K）不到 3% |
| 3 | **LCP 路线另有硬伤**（与收益无关）：会剥掉语义前缀（`find_`、`analysis_`），且字节不稳定——服务器加一个工具就可能让整组公共前缀变化，破 prompt 缓存 |

结论：**组内名字一律原样保留**。自重复命名的服务器显示出来只是“丑”，不是 bug ——
调用名来自 `tool_search` 返回值，与目录显示无关。

**截断（退化为兜底，不再是设计主体）**

- 验收口径（已按字符预算落定）：**456 工具 / 7 台服务器 ⇒ 零截断**（名字行 10,976 ≤ 12,500）。
- 超预算时（如 3000 工具）启用**按服务器注水分配**：短的组先满足，剩下的额度在还饿着的组之间
  继续平分 ⇒ 任何服务器都不会整台消失，溢出数写在各自组头（C 档）。
- 分配单位是**整行**，永不按字符切名字（I6）。

**其他**

- `select:` 支持裸名：唯一命中直返，多命中全返（否则目录改裸名会废掉这条主路径）。
- `catalogSectionText()` 保持纯函数：给定 catalog + config 出文本，不读宿主、不读时钟，可单测。
- 不新增 O(n) 热路径：摘要与分组只随 catalog revision 重算，不得进入每次 `searchCatalog`。
- 必须覆盖上一节 R3 的全部极端输入（0 台 / 1 台 1 工具 / 3000 工具 / 无 instructions / 非中文 / 哈希名 / 前缀歧义）。

**实现时发现一处此前的算错（重要，别照抄旧结论）**

先前说"裸名后 456 个工具装得下、零截断"，是把**字符**当预算算的。实际预算是
`maxCatalogLines`（**行数**）：格式变便宜了，但**行数上限没变**，所以默认仍然只列 300 个名字，
依旧 156 个不可见。同构夹具实测：

| 形态 | 名字行 | 名字字符 | 未列出 |
|---|---|---|---|
| 全名平铺 | 300 | 11,572 | 156 |
| 分组裸名 | 300 | **7,218（-37.6%）** | **156** |

也就是说：本次改动**只省字符，不多给名字**。要让那 156 个也可见，必须动预算单位或数值：

**已定案：方案 B（字符预算）**，用户 2026-10-26 拍板。落地口径：

- 新键 `maxCatalogChars`，默认 **12,500**；`maxCatalogLines` 进 `REMOVED_KEYS`。
- **预算只算名字行**：标题 / intro / 组头是"地图骨架"（≈700 字符，随服务器数线性）另付。
  算进去会让"预算小于骨架"无解——要么砍组头（地图缺块，违反 C 档），要么超支。
- 分配粒度是**整行**：装不下就少一行，**绝不切出半截名字**（I6）。
- 面板文案：「目录里工具名最多占多少字符」，中英同步。

**终态实测（同构夹具：7 台真实服务器名 / 456 个工具）**

| 口径 | 列出 | 名字行字符 | 整段字符 | 未列出 |
|---|---|---|---|---|
| 旧（300 行全名） | 314 | 11,872 | 12,896 | **142** |
| **新（12,500 字符裸名）** | **456** | **10,976** | **11,690** | **0** |

⇒ **多列 142 个名字，同时整段少 1,206 字符（-9.4%）**：两个轴同时改善。

**已知文档漂移（发版前必须一起改，别让第二个真相源留着）**

`docs/mcp-tool-search-design.md` 仍按旧口径描述：目录形态"names-only 平铺"、预算
`maxCatalogLines`（行）、默认 300。涉及行：**133、233、292、533、602**（另有 395/397/399
把 `maxCatalogLines` 当作"不进测试的安装期固定值"讨论）。需要改的口径三处：

1. 形态：平铺全名 → **按服务器分组 + 裸名**（分组头从"冗余"变成"服务器身份载体"，F15 的结论需加注）；
2. 预算：`maxCatalogLines`（行）→ **`maxCatalogChars`（字符，且只算名字行）**；
3. 默认值：300 行 → **12,500 字符**（来历：旧 300 行全名的实测成本 12,435）。

本轮已同步：`README.md` / `README.en.md` 的"三个上限"那段。

## 7. 明确不要做（防后人误改）

- **不要**在代码或配置默认值里写死任何具体工具名、服务器名、领域词、语言词表、停用词（红线 R1）。
- **不要**用"跳过某种段落 / 按标题判断 / 按长度猜重要性"来挑选摘要内容（红线 R2）。
- **不要**拿作者机器上的服务器组合当验收样本（红线 R3）；验收要跑 R3 的极端输入清单。
- **不要**把中文手写词表做成默认开启能力（违反 R1；失败时还会污染 top-N）。
- **不要**为了 Q2 去改 `catalogSectionLines()` 的排序语义（它是字节稳定/缓存友好的一部分），要改截断就单独加配额层。
- **不要**在 `assemble` waterfall 里做任何 O(工具数) 的重算（1.8.3 的 issue #8 就是这个形状）。
- **不要**把"BM25 / embedding"这种算法选择暴露给用户；用户能选的是**端点**。
- **不要**恢复 `descriptionChars`（`REMOVED_KEYS` 会拦）。
