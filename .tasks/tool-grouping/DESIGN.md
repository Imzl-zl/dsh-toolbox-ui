# 工具分组与批量加载（issue #12）设计稿

> 状态：**设计稿，未实现**。目标版本 1.12.0。
> 对应 issue：[#12 希望能按组管理工具](https://github.com/Imzl-zl/dsh-toolbox-ui/issues/12)
> 涉及页面：工具页第三段「其他插件与未识别」（`lib/client/60-tool-loading.js`）。
> 涉及策略：`lib/tool-loading-policy.js`。

## 0. 结论（先看这一段）

1. **先做批量，再做分组**。高频需求是"一次把这堆工具改掉"，分组只是"把这次选中的集合存下来"。只做分组、不做批量的话，用户必须先手工归组才有收益——绝大多数人不会做。
2. **分组是持久化的"选中集合 + 一个组级默认"，不是目录树**。一个工具只属于一个组；组里只有一个 `policy`，成员各自仍可单独覆盖（逐工具 > 分组）。
3. **只作用于非 MCP 工具**（`owner === null`）。MCP 已有"整台默认"（服务器组），两者不重叠，所以决策链里不产生任何新冲突：`tool_search`/`run_code` > 总开关 > 全部常驻 > 逐工具 > **自定义分组** > 宿主默认。
4. **数据放插件自己那条 patch 的兄弟键 `config.customGroups`**，与 `config.toolLoading` 平级。这样 `setDefer` 芯片那条写路径（`writablePolicy()`）**碰不到它**，不会出现"MCP 芯片一拨，用户分组全被抹掉"。代价见 §7.4。
5. 不猜插件归属。宿主没有 provenance（`lib/tool-loading-policy.js:11-13` 已写明），所以"自动按插件分组"不做，"按前缀建议"也不做（§8）。

## 1. issue 要什么、实际是什么

原文：

> 在其他插件和未识别工具中加上新建分组的功能，再按相应的组对同一插件下的工具同步修改加载方式。

拆成两条可验收的行为：

- **A. 可新建分组**，把「其他插件与未识别」里的工具归进去；
- **B. 对组批量改加载方式**（一次点击 = 整组常驻 / 按需）。

**没说的、但必须一起解决的**（否则 A 建出来也难用）：

- C. 不建组时也能批量（多选 + 整组动作）——这才是"安装了大量插件"的主路径；
- D. 组级默认与逐工具覆盖谁优先、失效了怎么办（工具没了、插件卸了）；
- E. 项目作用域下这些组怎么显示（分组是 profile 级的概念，工具本身也是）。

## 2. 用户与频率：为什么顺序是"批量在前"

| 需求 | 频率 | 当前成本 | 机制 |
| --- | --- | --- | --- |
| 找到某个工具的开关 | 高 | 搜索已有 | 已解决 |
| 一次改掉一批相关工具 | 高 | **逐行点 N 次** | 多选 + 批量（本设计 A） |
| 知道"为什么这个工具现在是这样" | 中 | 行内跟随文案已有 | 已解决 |
| 恢复默认 / 撤销误操作 | 中 | 保存 / 放弃修改 | 已解决 |
| 组织、记住一组工具 | **低** | 无 | 自定义分组（本设计 B） |

「组织」是低频但高成本的表面（配置、命名、失效清理）。所以：

- **v1 必须同时有多选批量**，否则分组功能像"先填表才能用"；
- **分组的创建入口就是"从选中创建"**，不提供空组编辑器（可以有，但默认流程不是它）；
- 没有建过任何组的用户，页面结构与今天完全一致（只是多一列勾选框 + 组头标签变成「未分组」）。

## 3. 数据模型

### 3.1 落盘形状（`config.customGroups`，与 `config.toolLoading` 平级）

```yaml
- id: dsh-toolbox-ui
  config:
    toolLoading:          # 现有：整体方案 / MCP 服务器组 / 逐工具
      groups:
        serena: deferred
      tools:
        read: resident
    customGroups:         # 新增：用户自定义分组（只作用于非 MCP 工具）
      表格工具:
        policy: deferred  # 可省略：省略 = 不设组级默认（跟随宿主：常驻）
        tools:
          - xlsx_read
          - xlsx_write
      网页抓取:
        policy: resident
        tools:
          - web_search
```

理由逐条：

- **键是组名**：YAML 映射天然禁止重名，改名 = 移键，不需要 id。与 `toolLoading.groups`（服务器名 → 策略）同一种读法。
- **`policy` 内联**：一个事实一个家。若把策略放进 `toolLoading.groups` 的命名空间键（`group:表格工具`），同一件事就横跨两个键，读的人迟早对不上。
- **`tools` 是数组**：顺序有意义（组内行按它排？不，行按名字排——数组只是集合，顺序不承诺）。重复成员在读侧按首次出现处理。
- **不存空组？** 存。用户可能先建组再归工具；删成员时自动删组会让"取消勾选"变成"组没了"。

### 3.2 校验（写侧严格，与 `validatePolicyConfig` 同一条纪律）

`lib/tool-grouping.js`（新文件）：

```js
export function validateCustomGroups(raw)          // 写侧：拒绝未知键 / 空组名 / 重复成员
export function normalizeCustomGroups(raw)         // 读侧：宽容，坏条目丢弃并给出 diagnostics
export function groupMembershipOf(groups)          // 成员 → 组名（先出现者胜）
```

规则：

| 输入 | 处理 |
| --- | --- |
| 组名为空/纯空白 | 写侧报错；读侧丢弃 |
| `tools` 里有重复名字 | 写侧报错（`工具 x 在分组「A」里出现两次`） |
| 同一工具出现在两个组 | 写侧报错（`工具 x 已在分组「A」中`）；读侧**先出现的胜**，并把被忽略的记进 `diagnostics` |
| `policy` 不是 resident/deferred | 写侧报错；读侧丢弃该组 |
| `tools` 不是字符串数组 | 写侧报错；读侧丢弃该组 |
| 组名长度 | **不做配置校验**，只在输入框 `maxlength` 限制（布局原因，不是数据规则） |
| 工具名在本机不存在 | **允许**（见 §7.2），UI 标注 |

### 3.3 作用域

- `customGroups` **只有全局层**。工具页项目作用域里仍显示这些组（成员同源、工具同源），但组头芯片只读，并复用已有的那句提示形状（`60-tool-loading.js:722` 的"搜索设置是全局配置；切到「全局」作用域里改。"）。
- `setWorkspaceToolLoading` 收到 `customGroups` 时**明确报错**，不静默丢弃：`.dsh/mcp.json` 的 `toolLoading` 是项目层的，分组不属于任何项目。
- 读侧：`workspaceToolLoading` 的返回里额外带 `customGroups`（全局的），与作用域内的 `policy` 分开——避免"项目策略里突然冒出全局分组"这种半状态。

## 4. 决策链（唯一一处修改点）

`lib/tool-loading-policy.js` 的 `resolveToolLoadingPolicy` 增加一个入参与一层：

```js
resolveToolLoadingPolicy({ …, customGroups })   // 归一化后的 { 组名: {policy?, tools:[]} }
```

优先级（自上而下，第一个命中者胜）：

```
保护名单 → 总开关 off → 全部常驻 → 项目逐工具 → 全局逐工具
→ 自定义分组（仅 owner === null 时）→ 项目组 → 全局组 → 旧 defer → 模式默认 → 宿主默认
```

**关键性质，必须有用例钉住**：

1. `customGroups` 只对 `owner === null` 生效；MCP 工具即便被手写进了组，也走服务器组那条链（分组策略对它不生效，并记一条诊断）。
2. 逐工具覆盖永远赢分组（"组里有个别例外"是正常配置，不是错误）。
3. 保护名单永远赢一切（`run_code` 放进按需组也仍是常驻）。
4. 分组策略只影响 `deferred` 集合的划分，不改变"延迟集合 ⇒ 进目录"这条既有机制。
5. 组内工具全部消失时，组策略不产生任何效果（不报错、不删配置）。

`REASONS` 增加两个枚举：`user-group`（全局组）——目前分组只有全局层，但读函数签名保留 `projectGroups` 的位置，避免下一版加项目层时改签名。**v1 只实现全局**。

行内"跟随"文案（`toolLoadingRow` 的 `followLabel`）新增一档：

- 在有分组、且该工具没有逐工具覆盖时：`跟随分组「表格工具」（按需）`
- 组里没有组级策略时：`跟随分组「表格工具」（宿主默认）`
- 已被逐工具覆盖时：维持今天的 `单独设置` 徽章（不改）

`inheritedPolicy` 的现算法（`lib/index.js:709-713`：删掉逐工具键后重算一次）**天然正确**——分组层在更下面，重算时仍会命中，所以行内"跟随分组"显示的就是"取消这条覆盖后会怎样"。这条不用改，但要用例钉住。

## 5. 读写链路

| 环节 | 位置 | 改动 |
| --- | --- | --- |
| 启动读取 | `lib/index.js` 网关构造（与 `globalToolLoading` 同处） | 新增 `this.customGroups = normalizeCustomGroups(readCustomGroupsFromPatch(…))` |
| 读全局 | `toolLoadingSettings()` | `policy` 原样返回；新增结果字段 `customGroups`、`groupDiagnostics` |
| 读项目 | `workspaceToolLoading()` | 同上，`customGroups` 取全局那的一份 |
| 写全局 | `updateToolLoadingSettings({ policy, customGroups })` | 一次事务里写两个键：`writeConfigKey` 各写一次（它保留兄弟键与注释，见 `tool-search-settings.js:256-299`）；`applyLive` 同时换内存 |
| 写项目 | `setWorkspaceToolLoading()` | payload 里出现 `customGroups` → 报错 |
| 芯片写 | `mcp-write-paths.js` 的 `setDefer` / `setDeferAll` | **不用改**（`customGroups` 不在 `toolLoading` 里，`writablePolicy()` 不可能碰它）。这是选兄弟键的直接收益；仍加一条回归用例 |
| 序列化 | `lib/tool-search-settings.js` | 新增 `readCustomGroupsFromPatch` / `setCustomGroupsInPatch`，复用 `writeConfigKey` |
| schema | `ToolSearchConfigSchema` | 增加 `customGroups` 键（严格形状） |

RPC 契约（`lib/rpc-contract.js`）：**不新增方法**，`updateToolLoadingSettings` 的 payload 增加一个键。结果 codec 是 `strictCodec(…, ANY_VALUE_SCHEMA)`（`lib/client.js:7854`），加字段不需要动 codec；但 `test/package-contract.test.mjs` 对结果形状有断言的话要同步。

## 6. UI

### 6.1 第三段的结构（仅在 `section === 'other'`）

```
其他插件与未识别                                    [+ 新建分组]
  ▾ ☑ 表格工具 (3)   3 常驻 / 0 按需   [跟随 ▾]      ⋯
      ☑ xlsx_read     读取表格    [跟随分组「表格工具」（常驻）][常驻][按需]
      ☑ xlsx_write    ...
  ▸ ☐ 未分组 (17)    17 常驻                       ⋯
```

- 组的存在形式：**自定义组（按创建顺序）+ 「未分组」永远在最后**。
- 组头：复选框（三态：全选/部分/无）、组名、数量、策略摘要（复用 `summaryOf`）、组级三态控件、溢出菜单（重命名 / 删除 / 选择本组）。组级控件沿用行内三态，标签写清"跟随"跟的是谁：`跟随宿主默认（常驻）`。
- 组名标签从今天的「其他插件与未识别工具」改为 **「未分组」**：段头已经说明了这批工具是什么，组头只回答"归没归组"。
- 没有自定义组时，页面不多出任何一行（段头 + 未分组组头，和今天的段头 + 组头等价）。

### 6.2 多选与批量（不建组也能用）

- 每行左侧一个复选框，**只在「其他」段出现**。理由写在这里免得以后被问：MCP 已有整台默认（再给逐工具批量会让"芯片写的"和"行里写的"两套语义打架），内置工具已有按用途分组且总量小而稳定。
- 行头复选框 = 选本组"当前筛选结果"；工具栏的"全选筛选结果"只在其他段出现（搜索 `chrome` → 全选 → 新建分组，是**没有 provenance 时的替代路径**：用户用关键词认出插件，工具替他从名字上归组）。
- 选中后出现动作条（吸附在列表上方）：`已选 12 个` · `常驻` · `按需` · `跟随` · `加入分组 ▾` · `新建分组` · `清空选择`。
- 所有批量动作**只改草稿**（`toolDraft`），不直接落盘；保存条已有的"已改 N 项 / 放弃修改"是唯一的确认与撤销手段。不给批量加二次确认弹窗——同一页里两种确认纪律比没有更让人迷惑。
- 移动语义：一个工具只能在一个组。选中其中有已属于别的组的，执行「加入分组」时**移动**并在提示里说清：`3 个已从「A」移出`。
- 选中集合按工具名记，跨筛选/搜索保留；动作条显示总数，另给"清空选择"。

### 6.3 新建 / 重命名 / 删除

| 动作 | 交互 | 落点 |
| --- | --- | --- |
| 新建 | 段头「+ 新建分组」或动作条「新建分组」→ 输入组名（默认建议：`分组 N`，空选择时建空组） | 草稿 |
| 重命名 | 溢出菜单 → 弹窗输入 | 草稿；重名当场报错 |
| 删除 | 溢出菜单 → 确认弹窗，文案写明成员去向：`3 个工具将回到「未分组」并跟随宿主默认` | 草稿 |
| 排序 | v1 不做（创建顺序即显示顺序） | — |

### 6.4 密度与可达性

- 复选框放在**已有的行头一行**里，不新增行高；列表页原本就是双列网格，勾选框占 20px 会挤压名字列——名字列本来就有 `title` 兜底，允许更早截断。
- 组头复选框、组级三态都进 Tab 序，`aria-label` 带上组名（`选择分组「表格工具」的全部工具`）。
- 所有新文案同时进 `lib/client/20-locale.js`（键 = 中文原文）与 `client-i18n` 用例；不写 `t()` 进常量表（会冻结语言，见 `60-tool-loading.js:16-17`）。

## 7. 边界与失败态

### 7.1 同一工具出现在两个组

写侧拒绝。读侧（手改文件才会出现）先出现的胜，其余记 `groupDiagnostics`，面板在段头下方显示一行：`2 个工具同时属于多个分组，已按先出现的分组处理`。不静默。

### 7.2 工具不存在了

**不自动清理**。原因：MCP 断开时工具本来就会临时从可见集里消失（非 MCP 插件被停用同理），自动删成员会把"临时不可见"变成"永久丢配置"。

- 组头显示：`（2 个不在本机）` + 溢出菜单里的「清理不在本机的成员」；
- 策略：这些名字在策略表里不产生任何效果。

### 7.3 空组

允许存在与保存，组头显示 `0 个工具`。删成员不删组。

### 7.4 降级

`ToolSearchConfigSchema` 是 `.strict()`（`tool-search-settings.js:51-68`），新增顶层键意味着**降级到没有该键的版本时插件加载会失败**（响亮失败，不是静默丢数据）。这是引入 `toolLoading` 时已经付过一次的代价，接受，但要在 release note 里写一句"降级需先清掉 `config.customGroups`"。

时机上还有一个更小的代价：`customGroups` 作为兄弟键，比塞进 `toolLoading` 更不容易被写路径误删（§5 表格最后两行）。

### 7.5 与筛选/搜索的关系

- 「加载方式」筛选按**行**过滤，组头总是显示出来（带命中数），否则筛选后组结构会消失，用户不知道自己筛掉的是哪一组；
- 类型筛选到 `builtin` / `mcp` 时，不显示自定义组（它们只属于「其他」段）。

## 8. 被否方案（附理由，避免以后重提）

| 方案 | 否因 |
| --- | --- |
| **自动按插件分组** | 宿主没有 provenance 接口。工具名与 description 是唯一线索，靠名字前缀猜等于给第三方工具编造归属；猜错的后果是把别人的工具批量藏起来（`tool-loading-policy.js:11-13` 的判断）。 |
| **按前缀"建议分组"** | 同上的弱化版：仍要猜，且建议错了用户会照单全收。关键词搜索 + 全选已经能给同一件事提供**由用户确认**的入口。 |
| **标签（一个工具多个组）** | 批量设加载方式时必须回答"两个组策略冲突听谁的"，这就引入第四条仲裁规则；收益（一个工具归两类）低于成本。 |
| **拖拽归组** | 长列表里不可精确、不可键盘操作、触屏差。 |
| **整组批量写成 N 条逐工具覆盖**（不引入组策略层） | 配置膨胀（30 行 vs 1 行）、新成员不自动继承、覆盖数指标被噪声淹没（组头好不容易做出"N 个单独设置"，结果全是批量写的）。 |
| **非 MCP 工具的"全局默认"开关** | 这正是策略层明确拒绝过的（`tool-loading-policy.js:181-184`）：来源不可证明时，一个全局开关能把日常工具整片藏掉。分组策略是**按组显式**的，风险面小一个数量级。 |
| **把分组塞进 `toolLoading`** | 会经过 `writablePolicy()`，而 `mcp-write-paths.js:67/115` 用它重写策略——一次 MCP 芯片操作就可能抹掉用户分组。兄弟键从结构上避免。 |
| **独立设置文件**（profile 下的 `groups.yml`） | 项目已经明确拒绝过"另开一个设置文件"（`tool-search-settings.js:1-2` 的取舍），配置留在插件自己那条 patch 里。 |

## 13. 第二版修订：先有流程，再有结构

第一版从数据结构出发（键怎么放、决策链怎么排）。这一版按"人什么时候来这页、来的时候在干什么"重排，
其中 **13.5 的六条是对第一版 §6 的直接修改**，以本节为准。

### 13.1 这页的业务本质

**它不是工具目录，是上下文预算的分配页。** 每一次模型请求，常驻工具都要付 schema 字符；按需工具只付
目录里的一个名字 + 被用到时的一次搜索往返。所以这页的每个控件都必须回答两件事：**它改变了哪部分预算**、
**它会不会把有用的工具藏掉**。

三条不变量（与既有设计一致，新功能不得破坏）：

1. **不猜来源**：宿主没有 provenance，就不自动归类（§8 已否掉自动分组）。
2. **组织不改变行为**：建组、归组、改组名，一律不改动任何工具的加载状态；只有显式点策略才变。
3. **显示即事实**：「跟随」必须写明跟谁、当前值是什么；组头写的值 = 下一次组装真正用的值。

### 13.2 四条体验原则

1. **先组织（无损），再决策（有损）**。新建分组的默认是「跟随宿主（常驻）」，用户先建立结构感，再决定
   哪一类该按需。反过来（建组即改行为）会让「整理一下」变成高风险动作，多数人就不整理了。
2. **批量与分组是同一动作的两档，可互相升级**。批量 = 一次性、不留结构；分组 = 留结构、新成员可继承。
   批量之后提供「存为分组」：把刚写的逐工具覆盖**上提**为组策略并删掉这些覆盖。不做这一步，
   用户会得到"组策略被逐工具覆盖压住、点组头没反应"的经典哑弹。
3. **每个动作说清影响面**：动作条 `已选 12 个`、组头 `整组 8 个`；P2 再加 `预计 −1,840 字符 schema`。
4. **状态可解释**：行内写 `跟随分组「xlsx 工具」（按需）`；三态旁说明 `按需 ≠ 关闭：模型经 tool_search
   检索后可用`；模型说"没有这个工具"时，用户能顺着这句话追到组。

### 13.3 四个真实场景（每条都是"点哪里 → 看到什么"）

**M1 新装了一个插件（发现 → 组织）**

1. 面板 →「工具」页签 → 类型筛选点「其他」；
2. 看到 `未分组 (26)`，展开；
3. 搜索框输入认得出的词（工具名前缀或描述里的词）→ 剩 8 个；
4. 点「全选筛选结果」→ 动作条：`已选 8 个` `常驻` `按需` `跟随` `加入分组 ▾` `新建分组` `清空选择`；
5. 点「新建分组」→ 弹窗，**组名预填刚才的搜索词** → 确定；
6. 组里 8 个工具，组头 `跟随宿主（常驻）`，行内 `跟随分组「xlsx 工具」（常驻）`，保存条 `已改 8 项`。
   到这里保存退出，得到的是**纯组织**，模型侧一个字没变。
7. 想让它按需，再点组头「按需」→ 8 行同时变 `跟随分组（按需）` → 保存。

**M2 上下文吃紧，要砍一批（决策）**

- 概览先给盘子：`可设置 268 · 常驻 241 · 按需 27`；
- 用户按"最不可能用到"圈定：不认识的插件、重型工具、只在某个项目用的；
- 每选一批，动作条只说 `已选 N 个`；P2 后说 `−1,840 字符 schema / 目录 +96 字符`；
- 点「按需」→ 草稿 → 保存条 `已改 N 项`；保存后 `已保存：N 个改为按需，下一轮请求生效`；
- 后悔的代价：保存前「放弃修改」；保存后回到那一组/那一行点「常驻」。

**M3 模型说"没有这个工具"（修复）**

- 搜工具名 → 行里写着 `按需` 或 `跟随分组「X」（按需）`；
- 前者点「常驻」；后者说明是组的锅 → 改组头，或在该行点「常驻」做例外（覆盖永远赢组）；
- 页面上任何地方都不应该说「关闭」——按需只是"模型要先搜一下"，这条要写进三态的说明里。

**M4 项目页签（作用域）**

- 分组照常显示（分组是全局的，工具也是全局的）；
- 组头三态禁用，并给一句 `分组是全局的；切到「全局」作用域里改`（复用 §6 里已有的提示形状）；
- 项目里的逐工具覆盖仍然赢全局组策略——那是项目级例外，不是 bug。

### 13.5 对第一版 §6 的六条修改（以此为准）

1. **「未分组」组头只放复选框，不放大按钮**。批量入口统一在动作条：`未分组` 往往是整段 200 个工具，

2. **组名预填当前搜索词**。用户为了圈定这 8 个工具已经输入过关键词，那个词就是他心里的组名。

   不加这条，"分好组、切走看一眼 MCP、回来发现没了"会变成这个功能最常见的投诉。

## 14. 第三版修订：方向修正——先把"一批"做对，分组只是把它存下来

### 14.1 上一版错在哪

**把 issue 里提出的解法当成了需求。** 他说的是「新建分组 → 按组批量改」，他要的是
「装了一堆插件，别让我一个个点，也别让我先做分类」。分组是他能想到的手段——因为他以为面板知道
哪个工具属于哪个插件——把手段做成入口，等于**先做一遍分类作业才开始享受方便**，恰好背离诉求。

### 14.2 "方便"要能量出来

三个指标，都能在界面上数动作：

1. 从进页到改完一批，点几下；
2. 要不要先建立结构（分类、命名、拖放、勾选）；
3. 下次还要不要重来。

| 做法 | 改 26 个工具 | 要先分类吗 | 下次 |
| --- | --- | --- | --- |
| 今天 | 26 次点击 | 不用 | 再点 26 次 |
| §13（勾选/建组为入口） | 搜索 → 全选 → 按需 → 保存（4 步），且要先学会勾选框 + 动作条 + 建组 | **要** | 1 次（点组头） |
| §14（作用于当前一批） | 搜索 → 点「设为按需」→ 保存（3 步，无新概念） | **不要** | 0（当场）或存组后 1 次 |

### 14.3 修正后的方向

**动作的对象是"你眼前这一批"，不是"你事先建的容器"。**

- **主路径**：筛选（搜索 / 类型 / 加载方式）→ 动作条出现 `匹配 26 个` → `设为常驻 / 设为按需 / 跟随`
  → 保存。不建组、不勾选、不命名。
- **勾选是收窄**（匹配 26 里只改 6 个），不是必经之路。
- **分组是把这次处理存下来**：动作条上的「存为分组」。**不提供空组，也没有"先建组再搬工具"**。
- 组存在之后，组头仍是一键整组——这就是他要的"按组同步修改"；成员继承组策略，逐工具覆盖仍赢。
  §13.2 的两条原则保留：存组默认不改行为；「存为分组」把刚写的覆盖**上提**为组策略。

### 14.4 细节规则（这一版要定的都在这里）

1. **动作条作用于谁**：有勾选 → 勾选（`已选 6 个`）；无勾选且有筛选 → 匹配行（`匹配 26 个`）；
   无勾选且无筛选 → **不出现**（不提供"全部 268 个"的一键，与策略层"不给非 MCP 全局开关"一致）。
2. **计数同源**：计数来自 `manageable`（已排除 protected），且与实际写入的是同一个数组，
   不许出现"显示 26、实际改 24"。
3. **筛选命中就展开命中的组**：今天只有搜索会展开（`groupOpen` 的 `searching ? true : …`），
   要改成"任何筛选命中都展开"，否则 `匹配 26 个` 和眼前 3 个组头对不上。
4. **折叠不影响计数**：匹配按行算，不按展开算。
5. **一步一次撤销**：批量后动作条给「撤销这一步」，还原到批量前的草稿；整页仍有「放弃修改」。
   不给二次确认弹窗——计数 + 草稿 + 撤销就是确认。
6. **如实报告**：`已改 7 项，1 个本来就是按需`；只在该出现时出现，不写死一句"成功"。
7. **「存为分组」只在有一批可存时出现**；组名预填 = 当前搜索词，无搜索时预填筛选名（`其他工具`）。
   存完自动展开该组，提示 `已存为分组「xlsx」（8 个）`。
8. **组策略与覆盖**：存组时若这批刚被批量设成同一个值，把它**上提**为组策略并删掉这些逐工具覆盖
   （`setTool(name, 'inherit')`）；否则组策略留空（跟随宿主）。不做这一步就会出现"点组头没反应"。
9. **删除组**：成员回落到宿主默认（或它们自己的覆盖），确认文案写清。
10. **项目作用域**：批量写项目 `tools`（项目覆盖），分组是全局只读；项目覆盖 > 全局组策略，
    这是项目级例外，不冲突。
11. **移动端**：动作条在 `dsh-mcp-tool-fixed` 内换行，按钮 ≥36px，计数不折行。
12. **性能**：批量只触发一次 `setState`（N 个键一起写）；不要每行各自重算。

### 14.7 为什么"自动按插件分组"这条近路走不通（已核实）

- `@deepseek-ai/dsh-tools@0.2.1-rc.5` 的 `ToolDefinition extends ToolSchema`：字段只有
  name / description / parameters / output / 执行与呈现回调；
- `ToolRuntime.register(definition)` 只区分"全局 / 调用者 agent 作用域"，注册表**不记录注册者**；
- MCP 能分组，是因为宿主把服务器名编进了工具名前缀（`mcp__<server>__`），非 MCP 没有这个约定。

所以"哪个工具属于哪个插件"在宿主里根本不存在，任何自动分组都是猜。这恰好证明了 §14.3 的方向：
**方便只能从交互里省出来，不能从数据里捡出来。**

## 15. 第四版：取消取舍，两个入口都要

前面几版一直在替用户做选择（批量还是分组、先筛还是先建组、功能还是适配）。这是个错误的问题设定：
**这些之间没有冲突，全都做。** 本节取代 §14.3 的"不提供空组"、§14.5 里作废 §6.3 的那两行、以及 §14.9 的
P1/P2 分期。

### 15.1 分组的两个入口，同一个东西

| 入口 | 位置 | 行为 | 空态 |
| --- | --- | --- | --- |
| 动作条「存为分组」 | 已筛出一批 / 已勾选若干时 | 用当前这批建组，名称预填搜索词 | 不适用（至少 1 个） |
| 段头「+ 新建分组」 | 「其他插件与未识别」段头 | 建一个空组，名称由用户输入 | 组头下显示一行：`还没有工具：勾选上面的工具后点「加入分组」，或把工具拖进来` |

两个入口写的是同一份 `customGroups`，没有第二种组。空组允许保存、允许删除；成员被移空后组保留
（用户可能在整理中途）。**不做取舍的理由**：想先规划结构的人从段头建，想就着眼前这批的人从动作条建，
两条路都通，成本只多一个空态分支（约 20 行 UI），不值得让任何一类用户改习惯。

### 15.2 批量与分组同版本发布

- 动作条作用于「勾选优先，否则当前筛选结果」，见 §14.4。
- 分组：建组（两个入口）、组头三态、成员继承组策略、逐工具覆盖优先、「存为分组」把覆盖上提为组策略。
- 两者独立可用：不建组也能批量；建了组也能只改单行。
- 版本号：一次发 **1.12.0**，不拆 P1/P2。

### 15.3 兼容与功能并行

- 兼容基线（devDeps → `0.2.2-rc.3`、cordis `~4.1.0`、loader/include `~1.1.0`、CI 的 `npm-rc` 硬编码）
  在独立 worktree `.worktrees/compat-0.2.2-rc.3` 上做，只改依赖与测试断言，不碰功能代码；
- 功能在 `main` 的 `feature/tool-grouping` 上做，只碰 `lib/tool-*`、`lib/client/60-tool-loading.js`、
  词典与文档；
- 两条线的文件交集只有 `test/tool-loading-panel.test.mjs` 与 `docs/*`，合并时按"兼容先落、功能后落"顺序
  解决，最后在 rc.3 基线上跑一次全量作为发布闸门。

### 15.4 新的验收口径

- 两个入口各建一个组，页面上是同一类组头（同名属性、同样的三态、同样的"整组 N 个"）。
- 空组能存、能删、能被"加入分组"填满。
- 批量不建组也完整可用；建组不批量也有意义（只是组织）。
- rc.3 基线上全量用例通过，且桌面版（已在跑 rc.3）里做一次真机点验。

## 16. UI 实施稿（第四版定稿，写代码就按这份）

### 16.0 设计立场（先看这三条，避免后面越做越乱）

1. **这页是"上下文预算的分配表"，不是目录管理器。** 新增元素只服务三件事：看清归属、批量决定、
   可回退。任何不服务这三件的控件不上。
2. **不引入新交互范式**：没有拖拽、没有右键菜单、没有模态批量对话框、没有二次确认。
   全页的确认纪律只有一条——草稿 + 撤销 + 保存。
3. **复用现有视觉语言**：组头、行、三态、折叠、吸顶工具栏全部沿用 `dsh-mcp-tool-*` 既有类；
   新元素只有三个：动作条、行复选框、组头菜单。

### 16.1 三种形态

**A. 没有任何自定义分组（默认，老用户看到的样子只多复选框）**

```
其他插件与未识别                                  [+ 新建分组]
▾ ☐ 未分组 · 26            26 常驻
    ☑ xlsx_read   读取表格   [跟随宿主默认（常驻）][常驻][按需]
    ☐ xlsx_write  写入表格   [跟随宿主默认（常驻）][常驻][按需]
```

**B. 有筛选/勾选（动作条出现，唯一批量入口）**

```
┌─────────────────────────────────────────────────────────────────────┐
│ 匹配 26 个 · 类型「其他」   [设为常驻] [设为按需] [跟随] [存为分组]  │
│ 已选 6 个 · 共匹配 26 个   [撤销这一步]            [清空选择]        │
└─────────────────────────────────────────────────────────────────────┘
```

**C. 有分组**

```
其他插件与未识别                                  [+ 新建分组]
▾ ☑ xlsx 工具 · 8     8 常驻 / 0 按需      [跟随|常驻|按需]  ⋯
    ☑ xlsx_read  读取表格  [跟随分组「xlsx 工具」（常驻）][常驻][按需]
▾ ☐ 空组示例 · 0      还没有工具：勾选上面的工具后点「加入分组」
▸ ☐ 未分组 · 18       18 常驻
```

排序：自定义组按创建顺序在前，`未分组` 永远最后。折叠状态默认全收起（与今天一致），
但**存组后自动展开新组**、**任何筛选命中都自动展开命中的组**。

### 16.2 动作条（新组件 `ToolBatchBar`）

| 项 | 规格 |
| --- | --- |
| 位置 | `dsh-mcp-tool-fixed` 固定区，工具栏下方、概览上方；不随列表滚动 |
| 出现条件 | 有勾选 **或** 有搜索词/类型筛选/加载方式筛选；两者都没有时不渲染（不提供"全部 268 个"一键） |
| 作用对象 | 有勾选 → 勾选集合；无勾选 → 当前匹配集合（`manageable` ∩ 筛选结果） |
| 计数 | 左：`匹配 N 个` 或 `已选 M 个 · 共匹配 N 个`；右：动作按钮。数字与实际写入同一个数组 |
| 动作 | `设为常驻` `设为按需` `跟随`（删覆盖）`存为分组`；有勾选时多一个 `清空选择` |
| 执行 | 只写草稿（`toolDraft`），一次 `setState`；不落盘、不弹确认 |
| 反馈 | 动作后左侧变 `已改 K 项`（K = 实际变化的个数），并出现 `撤销这一步` |
| 撤销 | 只保留最近一次批量的快照（`{names, before}`）；整页仍有 `放弃修改` |
| 空匹配 | 条内显示 `没有匹配的工具`，按钮禁用（不是隐藏——隐藏会让人以为筛选坏了） |
| 禁用 | `saving` 时全部禁用 |

### 16.3 组头（扩展现有 `groupNode`）

从左到右六个元素，顺序即优先级：

1. 折叠箭头（点击整行折叠）
2. 复选框（三态：全选/部分/无）——选择**本组当前匹配行**
3. 组名（双击进入行内改名；Esc 取消、Enter 提交；重名当场标红不提交）
4. 数量 `· N`
5. 摘要 `8 常驻 / 0 按需` + 有覆盖时 `· 3 个单独设置`；失效成员时 `· 2 个不在本机`
6. 右侧：三态控件（`跟随宿主（常驻）` / `常驻` / `按需`）+ `⋯` 菜单

菜单项（只有四项，不做分组套分组）：
`重命名` / `加入分组…`（把当前勾选移入本组）/ `清理不在本机的成员` / `删除分组`

规则：

- **组级三态是"整组默认"**，值写进 `customGroups[组].policy`；成员行显示 `跟随分组「X」（值）`。
  逐工具覆盖永远优先，组头摘要里的"N 个单独设置"就是它的可见性。
- **空组**：显示一行 `还没有工具：勾选上面的工具后点「加入分组」`；组头三态仍可设（为将来成员准备）。
- **项目作用域**：三态和菜单禁用，组头右侧显示 `分组是全局的`（title 指向全局页签）。
- **删除**：确认文案写清成员去向（`8 个工具将回到「未分组」并跟随宿主默认`）；确认框用现有 `Dialog`。
- **组级改动同样只进草稿**，保存条统一落盘。

### 16.4 行（扩展现有 `toolLoadingRow`）

- 复选框只在 `section === 'other'` 出现，放在 `dsh-mcp-tool-head` 首位，不新增行高。
- 三态按钮原样复用；跟随文案三档：`跟随分组「X」（按需）` / `跟随宿主默认（常驻）` / `单独设置`。
- 勾选时整行加 `.is-selected`（浅底色，不是边框加粗——边框已被"已改/覆盖"占用）。
- 行内不新增菜单；移动成员只走动作条或组头菜单。

### 16.5 状态矩阵

| 状态 | 表现 |
| --- | --- |
| 读取中 | 现有"正在读取…"；动作条不渲染 |
| 无任何工具 | 现有空态；段头按钮隐藏 |
| 筛选无命中 | 列表"没有匹配的工具"；动作条显示空匹配禁用态 |
| 有未保存改动 | 保存条 `已改 N 项`；动作条照常可用 |
| 保存中 | 全部按钮禁用，文案 `保存中…` |
| 保存失败 | 现有错误条 + `role=alert`；草稿保留 |
| 项目作用域 | 分组只读；动作条照常（写项目覆盖）；提示"分组是全局的" |
| 宿主无 `customGroups`（旧配置） | 等同无分组形态；写入后出现该键 |
| 200+ 成员组 | 组默认收起；计数与摘要不展开算；展开后 `content-visibility` 沿用 |

### 16.6 交互细则（实现时逐条对）

1. 勾选优先于筛选：有勾选时按钮只动勾选；动作条文案必须写明作用对象。
2. 切换筛选**不清空**勾选；`清空选择` 是唯一清空入口；已勾选但被筛掉的行不计入动作条计数，
   文案写成 `已选 6 个 · 共匹配 26 个` 以避免歧义（隐藏的勾选保留，重新筛出来还在）。
3. 点组头复选框 = 全选/取消本组**当前匹配**行。
4. 筛选命中自动展开命中的组；清空筛选后恢复用户原来的折叠状态。
5. 建组（两个入口）不改任何一行的 `policy`。
6. 动作条 `存为分组`：组名预填当前搜索词（无搜索则 `其他工具`）；成员 = 当前作用对象；
   若这批刚被批量设成同一个值，**上提为组策略并删除这些逐工具覆盖**；否则组策略留空。
7. `加入分组…` 是移动语义：从原组移除，并在提示里说 `3 个已从「A」移出`。
8. 删除组不删成员上的逐工具覆盖。
9. 组名：trim、非空、≤40 字符（输入框 maxlength，不做配置层上限）；重名拒绝并聚焦输入框。
10. 空组允许保存；成员移空后组保留。
11. 保存后回读服务端结果，组与行状态以回读为准（不本地乐观保留）。
12. 键盘：动作条 `role=toolbar`；复选框可 Tab 聚焦；组头菜单 Esc 关闭并归还焦点。
13. 移动端（≤760px）：动作条换两行（计数一行、按钮一行）；按钮 ≥36px；计数 `white-space:nowrap`。
14. 文案一律走 `t()`，新键同时进 `20-locale.js` 与 `client-i18n` 用例；不在常量表里调 `t()`。
